# Codex 通知策略

当任务出现需要人决策的状态时，优先调用 `publish_notification` MCP 工具；钩子只负责机械的权限捕获和 Stop 漏发兜底。

## 应当发布

- `NeedsConfirmation`：下一步需要用户明确选择，且未获授权。
- `Blocked`：同一外部或用户输入阻塞反复出现，当前无法产生有意义进展。
- `GoalCompleted`：用户要求的目标确实完成，且有验证结论。
- `ExecutionFailed`：不可恢复失败，或重试/替代方案耗尽。
- `PermissionRequired`：即将出现的权限请求；仅描述动作类别、目的与影响范围。

## 不应发布

- 每个工具调用、普通进度、代码片段、完整日志或提示词。
- 可以通过修复、一次重试、替代测试或继续当前流程解决的测试失败。
- 任何密码、令牌、Webhook、个人资料、原始工具参数或 URL 查询参数。

## 调用约定

为事件提供简短 `title` 与 `summary`，可选字段只包含无敏感的项目名、阶段或关联 ID。默认使用稳定的 `subject`（如任务目标或工单号），以获得跨调用一致的去重键。不要手写 `dedupe_key`，除非你有稳定、无敏感的业务主键。需要确认时，通知不能替代对话内的明确说明与提问。
